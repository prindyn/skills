# Framework Wiring

How to plug DESIGN.md tokens into popular UI stacks. Pick the section
matching the user's project. The general pattern is the same across all
of them: **tokens are emitted once, consumed everywhere**.

`scripts/extract_tokens.py` produces the raw outputs referenced below.

---

## Vanilla HTML + CSS

Generate CSS custom properties:

```bash
python scripts/extract_tokens.py DESIGN.md --format css > tokens.css
```

Produces:

```css
:root {
  --color-primary: #1A1C1E;
  --color-secondary: #6C7278;
  --color-tertiary: #B8422E;
  --color-neutral: #F7F5F2;

  --font-h1-family: "Public Sans", system-ui, sans-serif;
  --font-h1-size: 3rem;
  --font-h1-weight: 700;
  --font-h1-line-height: 1.1;
  --font-h1-letter-spacing: -0.02em;

  --space-sm: 8px;
  --space-md: 16px;
  --space-lg: 24px;

  --rounded-sm: 4px;
  --rounded-md: 8px;
  --rounded-lg: 16px;
}
```

Import once at the document root, then every component references
variables. Never repeat raw hex.

## Tailwind CSS

```bash
python scripts/extract_tokens.py DESIGN.md --format tailwind > theme.json
```

Then in `tailwind.config.js`:

```js
const theme = require('./theme.json');

module.exports = {
  theme: {
    extend: {
      colors: theme.colors,
      fontFamily: theme.fontFamily,
      fontSize: theme.fontSize,
      spacing: theme.spacing,
      borderRadius: theme.borderRadius,
    },
  },
};
```

Now `bg-primary`, `p-md`, `rounded-sm`, `text-h1` are all tied to
DESIGN.md. Component variants:

```tsx
<button className="bg-tertiary text-white rounded-sm p-md hover:bg-primary
                   focus-visible:outline focus-visible:outline-primary
                   disabled:bg-neutral disabled:text-secondary">
  {label}
</button>
```

If the user uses Tailwind v4 with `@theme`, write the same tokens into a
`theme.css` block instead of `tailwind.config.js`.

## React (CSS Modules / styled-components / vanilla extract)

The pattern is the same in all three:

1. Generate a JS/TS theme from `extract_tokens.py --format json`.
2. Re-export typed token references from a single `tokens.ts`.
3. Components import named tokens, never literal values.

```ts
// tokens.ts
import raw from './tokens.json';

export const colors = raw.colors as {
  primary: string; secondary: string; tertiary: string; neutral: string;
};
export const spacing = raw.spacing;
export const rounded = raw.rounded;
export const typography = raw.typography;
```

```tsx
// Button.tsx (styled-components example)
import styled from 'styled-components';
import { colors, spacing, rounded } from './tokens';

export const Button = styled.button`
  background: ${colors.tertiary};
  color: white;
  padding: ${spacing.md};
  border-radius: ${rounded.sm};
  &:hover { background: ${colors.primary}; }
  &:focus-visible { outline: 2px solid ${colors.primary}; outline-offset: 2px; }
  &:disabled { background: ${colors.neutral}; color: ${colors.secondary}; }
`;
```

## Vue 3

Use CSS variables generated by `extract_tokens.py --format css`, import
once in `main.ts`:

```ts
import './tokens.css';
```

Then in SFCs:

```vue
<template><button class="btn"><slot /></button></template>

<style scoped>
.btn {
  background: var(--color-tertiary);
  color: #fff;
  padding: var(--space-md);
  border-radius: var(--rounded-sm);
}
.btn:hover { background: var(--color-primary); }
.btn:focus-visible { outline: 2px solid var(--color-primary); outline-offset: 2px; }
.btn:disabled { background: var(--color-neutral); color: var(--color-secondary); }
</style>
```

## SwiftUI (iOS)

DESIGN.md doesn't ship a native Swift export, so emit JSON and bridge:

```bash
python scripts/extract_tokens.py DESIGN.md --format json > Tokens.json
```

Bundle `Tokens.json` and decode at startup into a `DesignTokens` struct:

```swift
struct DesignTokens: Codable {
    let colors: [String: String]
    let spacing: [String: String]
    let rounded: [String: String]
}

extension Color {
    init(token: String) { /* parse hex from DesignTokens.shared.colors[token] */ }
}
```

Use `Color(token: "primary")` everywhere. For dimensions, parse the unit
("16px") and convert to `CGFloat` at load.

For dynamic type respect, map DESIGN.md typography sizes to
`Font.system(size:)` modified by the user's accessibility scaling.

## Jetpack Compose (Android)

Same pattern: JSON → typed Kotlin objects.

```kotlin
data class DesignTokens(
    val colors: Map<String, String>,
    val spacing: Map<String, String>,
    val rounded: Map<String, String>,
)

val LocalTokens = staticCompositionLocalOf<DesignTokens> { error("…") }
```

Wrap your root in `CompositionLocalProvider(LocalTokens provides tokens)`,
then components access `LocalTokens.current.colors["primary"]`.

For Material 3, also map DESIGN.md tokens onto a `ColorScheme`:

```kotlin
val tokens = LocalTokens.current
val scheme = lightColorScheme(
    primary = Color(parseHex(tokens.colors["primary"]!!)),
    secondary = Color(parseHex(tokens.colors["secondary"]!!)),
    // …
)
MaterialTheme(colorScheme = scheme) { … }
```

## Figma / Tokens Studio (round-trip)

If the user maintains tokens in Figma via Tokens Studio:

1. Export Tokens Studio JSON from Figma (Tokens Studio → Export → JSON).
2. Reshape to DESIGN.md front-matter (Tokens Studio's nested
   structure flattens to DESIGN.md's `colors:` / `typography:` /
   `spacing:` / `rounded:`).
3. Commit DESIGN.md as the canonical source. Figma becomes a viewer.

Going the other direction (DESIGN.md → Figma) is harder because Figma
needs imported token JSON in its specific shape — the
`@google/design.md` CLI can export DTCG, which Tokens Studio can import.

## When the project has no token system yet

Don't try to retrofit during the same task as "build the homepage". Two
sequential moves:

1. First task: write DESIGN.md (use the `design-md` skill, or scaffold
   from `templates/DESIGN.starter.md` here).
2. Then task: build the UI from it (this skill).

Forcing both at once produces a worse design system *and* a worse UI.
